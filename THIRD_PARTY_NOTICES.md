Ported:

- `raw_message.py`, `const.py`, `util.py`, in `src/velbus/frame.js`: the
  frame layout (start byte, priority, address, RTR and length, data,
  checksum, end byte), the priorities, the checksum.
- `protocol.py`, `controller.py`, in `src/velbus/client.js`: the TCP and TLS
  connection (the Signum certificate not checked against a CA), the Signum
  authentication key written first, the 60 ms between frames and the longer
  pause after a channel name request.
- `handler.py`, `module.py`, in `src/velbus/client.js` and `src/app.js`: the
  bus scan (a module type request to each address 1 to 254, then 3 s), the
  sub-addresses (`B0`, `A7`, `A6`) and their channel offset of 8, the status
  and channel name requests, the assembly of a channel name in three parts,
  the temperature precision kept between the two temperature messages
  (`maybe_update_temperature`), the push button status read for relays too.
- `messages/*.py`, `message_fields.py`, `channels.py`, in
  `src/velbus/messages.js`: the meaning of the messages read (relay, dimmer,
  slider, dim values, blind, thermostat, sensor temperature, push button,
  channel names, module type, sub-type) and the frames of the commands sent
  (relay on / off, set and restore dimmer, blind up / down / stop / position,
  set temperature, comfort / day / night / safe with the program state kept
  as `_switch_mode` does), with the variants of each.
- `module_spec/*.json`, in `src/velbus/module-table.js` (generated by
  `scripts/generate-module-table.mjs`, not copied by hand): for each module
  type, its name, the channels shown here, the message variant of each
  command used (`CommandToClass`), the temperature channel, the thermostat
  flag, the channel number map and the dimmer scale.

Changed: network gateways only (no serial or USB); one connection with
spaced reconnections and a watchdog; the password only ever written on TLS,
and a gateway that closes right after it twice stops the connection; an
optional SHA-256 pin of the Signum certificate; the frame stream cut in one
forward pass with a bounded buffer (velbus-aio cuts 14-byte windows); two
bounded write queues, commands first, never written after their deadline,
their option checked right before the write; an answer only taken from a
frame received after its request; DALI modules not supported; a thermostat
decided on a status read just before each command.
